Prerequisites

  • Docker & Docker Compose (recommended path)
  • Python 3.10+ (for the SDK example)
  • Or, to build from source: Go 1.25+, PostgreSQL 13+, NATS 2.10+ (JetStream, optional — PostgreSQL is the default queue), Redis 7+

1. Get the Janus Source

The Janus repository ships with a production-ready Dockerfile and docker-compose.yml. Clone it to get everything you need:

git clone https://github.com/agentium-lab/Janus.git
cd Janus

The clone gives you:

  • Dockerfile — multi-stage build (Go builder → minimal Alpine runtime), produces the janus-api binary
  • docker-compose.yml — one command brings up Janus + PostgreSQL + NATS + Redis
  • configs/janus.example.yaml — reference configuration file
  • migrations/ — PostgreSQL schema migrations (auto-applied on boot)

2. Start Janus with Docker Compose

From the repo root, a single command builds the Janus image and starts all four services (janus-api, postgres:16, nats:2 with JetStream, redis:7 — in production NATS is optional: PostgreSQL is the default queue, and the Compose stack simply includes it for the event fan-out demos):

docker compose up -d --build

The first build takes a couple of minutes (compiles the Go binary). Subsequent starts are instant. Verify every service is healthy:

curl -s http://localhost:8080/healthz
# → {"status":"ok"}

curl -s http://localhost:8080/readyz
# → {"status":"ready"}  (checks PG + NATS + Redis connectivity)

Get your API key. Auth is on by default, and the stack seeds a public dev key for tenant acme. Export it now — every later step uses it:

# The seeded dev key (public by design — dev only):
export JANUS_API_KEY=janus_e12ebdab09a71c856666756ab26fd12db630041a96559b74066f66820c1d6d48

Janus exposes two ports:

  • 8080 — HTTP REST API & protocol gateways
  • 9090 — gRPC API

5. Install the Python SDK

pip install janus-broker

6. Publish a Task

Create a file publish.py:

import os

from janus_broker import (
    CreateMailboxRequest, JanusClient, Payload, PublishTaskRequest,
    RegisterAgentRequest, Target, TaskEnvelope,
)

# API key from step 2 (seeded dev key, or one created via the CLI)
client = JanusClient(
    "http://localhost:8080",
    tenant_id="acme",
    api_key=os.environ["JANUS_API_KEY"],
)

# 1) Register the agent that will consume the task
client.register_agent(RegisterAgentRequest(
    id="reviewer",
    display_name="Code Reviewer",
    capabilities=[{"capability": "code_review", "description": "reviews source code"}],
))

# 2) Create its mailbox
client.create_mailbox(CreateMailboxRequest(id="review-mb", agent_id="reviewer"))

# 3) Publish a task into that mailbox
resp = client.publish_task(PublishTaskRequest(
    id="task-001",
    source_agent="product",
    target_type="mailbox",
    target_value="review-mb",
    envelope=TaskEnvelope(
        task_id="task-001",
        tenant_id="acme",
        source_agent="product",
        target=Target(type="mailbox", value="review-mb"),
        payload=Payload(type="code_review", content='{"pr_url": "https://github.com/org/repo/pull/42"}'),
    ),
))
print("Published:", resp["id"])
$ python publish.py
# → Published: task-001

Target Types

Janus supports five ways to route a task to its destination:

  • mailbox — deliver directly to a specific mailbox. Best for point-to-point workflows.
  • agent — deliver to a specific agent. Janus resolves agent-2 to its active mailbox automatically.
  • capability — describe what you need, Janus finds an online agent with that capability.
  • group — deliver to a team. Set team: "sre" in your agent config, then publish with target_type: "group", target_value: "sre".
  • intent — describe what you need in natural language. Requires LLM configuration (JANUS_LLM_ENABLED=true). Janus maps your request to the best matching capability.
# Route to a specific agent
client.publish_task({
    "id": "task-002",
    "source_agent": "product",
    "target_type": "agent",
    "target_value": "reviewer",
    "envelope": {"task_id": "task-002", "tenant_id": "acme",
                 "source_agent": "product",
                 "target": {"type": "agent", "value": "reviewer"},
                 "payload": {"type": "code_review", "content": "{}"}},
})

# Route by capability (Janus finds an online agent that declares it)
client.publish_task({
    "id": "task-003",
    "source_agent": "product",
    "target_type": "capability",
    "target_value": "code_review",
    "envelope": {"task_id": "task-003", "tenant_id": "acme",
                 "source_agent": "product",
                 "target": {"type": "capability", "value": "code_review"},
                 "payload": {"type": "code_review", "content": "{}"}},
})

# Route to a team (agents registered with team: "sre")
client.publish_task({
    "id": "task-004",
    "source_agent": "product",
    "target_type": "group",
    "target_value": "sre",
    "envelope": {"task_id": "task-004", "tenant_id": "acme",
                 "source_agent": "product",
                 "target": {"type": "group", "value": "sre"},
                 "payload": {"type": "deploy", "content": "{}"}},
})

7. Pull and Complete the Task

Create a file worker.py:

import os

from janus_broker import AckRequest, JanusClient

client = JanusClient(
    "http://localhost:8080",
    tenant_id="acme",
    api_key=os.environ["JANUS_API_KEY"],
)

result = client.pull_task("review-mb", "reviewer")
if result is None:
    print("No task waiting — mailbox is empty")
else:
    print("Got task:", result.task.id)
    client.start_task(result.task.id, result.lease.lease_id, agent_id="reviewer")

    # ...do the work here...

    client.ack_task(result.task.id, AckRequest(
        lease_id=result.lease.lease_id,
        result_ref="s3://review-result.json",
        agent_id="reviewer",
    ))
    print("Task completed")
$ python worker.py
# → Got task: task-001
# → Task completed

Report progress

Handlers receive (task, progress) and return a (result_ref, token_usage) tuple — the Worker injects the callback:

def process(task, progress):
    progress("Analyzing code...", percent=20)
    progress("Fixing issues...", percent=60)
    return "s3://review-result.json", None  # (result_ref, token_usage)

# Read the event trail from the other side (progress + lifecycle):
for evt in client.get_task_events("task-001"):
    print(evt["event_type"], evt.get("payload"))
# → task.progress {"percent": 20, "message": "Analyzing code..."}
# → task.completed {...}

8. Verify via CLI

Use the Janus CLI to check task state:

janus task list --tenant acme
# → task-001  completed  2026-07-31T12:00:00Z

janus mailbox list --tenant acme
# → review-mb  tasks: 1  pending: 0

Troubleshooting the first run

  • 401 / 403 on every call — the Compose stack starts with auth enabled; export the seeded dev key (deployments/dev/seed-dev-key.sql) or one created via janus api-key create as JANUS_API_KEY, and pass api_key= to the client.
  • Pull returns None — the mailbox is empty or the task hasn't reached the queue yet; poll again. An empty pull is a normal result, not an error.
  • Capability/group routing finds no agent — routing only considers registered, online agents; call register_agent (with the capability) and heartbeat before publishing.
