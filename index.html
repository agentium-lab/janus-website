Architecture

One broker, three planes

Agents talk to Janus; Janus owns durability; PostgreSQL is the single source of truth.

AI AGENTS

LangGraph · AutoGen · CrewAI · MCP tools · custom runtimes — any A2A/SDK/gRPC client

submit · pull · progress · ack — with leases, budgets, and identity enforced in between

⇄

INGRESS

A2A v1 gateway · MCP gateway · HTTP REST · gRPC — auth, scopes, agent-identity binding

SERVICES

Task state machine · policy & approval · budgets & ledger · routing & intent · audit

WORKERS

Transactional outbox publisher · event projector · lease & retry scanners · heartbeat sweeper

⇄

POSTGRESQL

Authoritative state + transactional outbox — accepted ≠ queued, replay-safe audit

NATS · REDIS

JetStream optional delivery plane · Redis heartbeat & rate-limit cache (no durable facts)

State changes commit to PostgreSQL first; the outbox publishes to NATS after commit — PG state is always the recovery source.

Capabilities

Core Capabilities

Six pillars that turn fragile agent-to-agent calls into a governed, observable, durable mesh.

📡 Live Streaming

  • New in v1.4: real-time task progress via SSE
  • Agents report progress like logging: progress("Analyzing...", 60)
  • Subscribe from any SDK, Console, or A2A client
  • Streams auto-close on task completion

🔄 Durable Delivery

  • PostgreSQL-only mode (CI-verified without Redis) — NATS optional accelerator
  • PostgreSQL transactional state with a transactional outbox; NATS is optional delivery
  • Automatic recovery after agent crashes
  • Idempotent ACK/NACK — at-least-once delivery (external side effects must be idempotent)
  • Auto-retry + dead letter queue + replay

⚖️ Governance

  • Policy engine: who can call whom, with what data
  • Budget: RPM / TPM / concurrency admission limits per tenant/agent (broker-counted; a Redis outage fails open); token & cost figures are agent-reported visibility, TPM is an admission estimate
  • Human approval for high-risk tasks
  • Full audit trail for every step

🧭 Capability Routing

  • Match agents by capability, not hard-coded target
  • Hard constraints: online / policy / capacity / budget
  • Semantic scoring of candidates
  • Capability-based routing (NL intent resolver on roadmap)

🔌 Multi-Protocol

  • HTTP REST API + gRPC
  • A2A v1 subset Gateway — Agent Card, Send/Stream, Get/List/Cancel/Subscribe, verified against the official a2a-go client
  • ACP Gateway (Manifest / Runs) — deprecated → A2A (Sunset 2026-12-31)
  • MCP Gateway (Tool Call / Resource)

📊 Observability

  • Prometheus metrics (16+ core metrics)
  • Service spans with optional OTLP export (HTTP traceparent propagation: roadmap)
  • Structured JSON logging
  • Pre-built Grafana dashboard

🛡️ Security

  • Tenant isolation (data / messages / files)
  • API Key auth + mTLS
  • Automatic cross-tenant access denial
  • Security audit events
Quick Start

Running in 5 Minutes

One command to start the broker, a few lines of SDK to publish and complete your first durable task.

1. Start Janus 
$ docker compose up -d
2. Publish a task (Python SDK) 
from janus_broker import JanusClient, PublishTaskRequest

client = JanusClient("http://localhost:8080", tenant_id="acme", api_key="janus_dev_...")

client.publish_task(PublishTaskRequest(
    id="task-001",
    source_agent="product",
    target_type="capability",
    target_value="code_review",
))
3. Agent pulls and completes 
from janus_broker import AckRequest

result = client.pull_task("review-mb", "reviewer")
if result is not None:  # empty pulls return None
    client.start_task(result.task.id, result.lease.lease_id, agent_id="reviewer")
    # ...process the task...
    client.ack_task(result.task.id, AckRequest(
        lease_id=result.lease.lease_id,
        result_ref="s3://result.json", agent_id="reviewer",
    ))
