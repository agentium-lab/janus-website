API 参考

Janus 提供 HTTP REST 与 gRPC API。所有 SDK 都通过这些端点通信。

基础 URL

http://localhost:8080

所有请求都需要 X-Tenant-ID 请求头。需要认证的端点还要求 Authorization: Bearer <api_key> 请求头。

REST 端点

健康与就绪

GET/healthz
存活探针。进程存活时返回 200。
GET/readyz
就绪探针。检查 PG、NATS、Redis 连通性，仅当所有依赖可访问时返回 200。

邮箱

POST/api/v1/mailboxes
创建邮箱。请求体：{ "name": "review-mb", "agent_id": "reviewer" }
GET/api/v1/mailboxes/{name}
获取邮箱详情与统计。
GET/api/v1/mailboxes
列出该租户下所有邮箱。
DELETE/api/v1/mailboxes/{name}
删除邮箱（必须为空）。

任务

POST/api/v1/tasks
发布任务。请求体：{ "id", "source_agent", "target_type", "target_value", "envelope" }
POST/api/v1/mailboxes/{name}/pull
从邮箱拉取下一个待处理任务。请求体：{ "agent_id": "reviewer" }
POST/api/v1/tasks/{id}/start
开始处理任务。请求体：{ "lease_id": "..." }
POST/api/v1/tasks/{id}/ack
确认成功完成。请求体：{ "lease_id": "...", "result_ref": "..." }
POST/api/v1/tasks/{id}/nack
否定确认 — 回到队列或进入 DLQ。请求体：{ "lease_id": "...", "reason": "..." }
GET/api/v1/tasks/{id}
获取任务详情与当前状态。
GET/api/v1/tasks
列出任务，支持可选过滤（状态、邮箱、来源）。
POST/api/v1/tasks/{id}/replay
将任务从 DLQ 重放回 pending 状态。

意图解析

POST/api/v1/intent/resolve
将自然语言解析为能力。请求体：{ "query": "Review Go code for bugs", "tenant_id": "acme" }

工件（Artifacts）

POST/api/v1/artifacts
上传工件。Multipart 表单，带租户隔离。
GET/api/v1/artifacts/{id}
下载工件（租户作用域访问检查）。

错误格式

所有错误都返回标准信封：

{
    "error": {
        "code": "TENANT_MISMATCH",
        "message": "Cross-tenant access denied",
        "details": {
            "request_tenant": "acme",
            "resource_tenant": "evil-corp"
        }
    }
}
HTTP 状态错误码描述
400INVALID_REQUEST请求体格式错误
401UNAUTHENTICATED缺少或无效的 API 密钥
403TENANT_MISMATCH跨租户访问被拒绝
403POLICY_DENIED治理策略阻止了该操作
404NOT_FOUND资源不存在
409LEASE_EXPIRED任务租约已过期，需要重新拉取
429RATE_LIMITED超出预算或并发限制
500INTERNAL服务器错误

认证

Janus 支持两种认证模式：

  • API 密钥（默认，已启用）— 通过 Authorization: Bearer <key> 请求头传递
  • mTLS — 使用客户端证书的双向 TLS

API 密钥按租户作用域划分。通过 CLI 创建与撤销密钥：

janus api-key create --tenant acme
janus api-key revoke --tenant acme --key-id &lt;id&gt;
完整的 protobuf 服务定义与 gRPC reflection 已在服务端开放。proto 文件见 GitHub 仓库。
