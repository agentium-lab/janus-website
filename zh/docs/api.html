API 参考

Janus 提供 HTTP REST 与 gRPC API。所有 SDK 都通过这些端点通信。

基础 URL

http://localhost:8080

所有请求都需要 X-Tenant-ID 请求头。需要认证的端点还要求 Authorization: Bearer <api_key> 请求头。

REST 端点

健康与就绪

GET/healthz
存活探针。进程存活时返回 200。
GET/readyz
就绪探针。检查 PG、NATS、Redis 连通性，仅当所有依赖可访问时返回 200。

邮箱

POST/v1/tenants/{tenant}/mailboxes
创建邮箱。请求体：{ "id": "review-mb", "agent_id": "reviewer", "ack_wait_seconds": 300, "max_deliver": 5 }
GET/v1/tenants/{tenant}/mailboxes/{id}
获取邮箱详情与统计。
PATCH/v1/tenants/{tenant}/mailboxes/{id}
更新邮箱配置（max_concurrency、ack_wait_seconds、max_deliver、retention_seconds）。

Agent

POST/v1/tenants/{tenant}/agents
注册 Agent 并附带能力。请求体：{ "id", "display_name", "team", "protocol", "capabilities": [{ "capability", "description" }] }。v1.1.0 起能力原子化持久化。
POST/v1/tenants/{tenant}/agents/{id}/heartbeat
发送心跳，保持 Agent 在线（TTL 由 JANUS_HB_TTL 控制）。
GET/v1/tenants/{tenant}/agents
列出已注册的 Agent。

任务

POST/v1/tenants/{tenant}/tasks
发布任务。请求体（必填 id、source_agent、target_type、target_value；envelope 可选但推荐）：{ "id": "task-001", "source_agent": "product", "target_type": "capability", "target_value": "code_review", "envelope": { "task_id": "task-001", "tenant_id": "acme", "source_agent": "product", "target": { "type": "capability", "value": "code_review" }, "payload": { "type": "code_review", "content": "{}" } } }。响应 201：完整任务对象（成功时 status: queued；策略要求审批时 approval_pending）。同 id 重复发布幂等（返回已存在任务）。
POST/v1/tenants/{tenant}/mailboxes/{name}/pull
从邮箱拉取下一个待处理任务（长轮询最长约 2 秒）。请求体：{ "agent_id": "reviewer" }。响应 200：{ "task": { "id": "...", "status": "claimed", ... }, "lease": { "lease_id": "...", "attempt": 1, "expires_at": "..." } }。邮箱为空：204 No Content——正常结果，重试即可。投递为至少一次：租约过期未 ACK 时同一任务会重投（attempt 递增）。
POST/v1/tenants/{tenant}/tasks/{id}/start
拉取后开始处理。请求体：{ "lease_id": "...", "agent_id": "reviewer" }。任务转为 running。租约过期或不匹配返回 400——请重新拉取。
POST/v1/tenants/{tenant}/tasks/{id}/heartbeat
处理中续租（长任务）。请求体：{ "lease_id": "...", "agent_id": "reviewer" }。响应 200：{ "status": "ok" }。不续租则租约到期（邮箱 ack_wait_seconds，默认 300 秒）后任务被重投给其他 worker。
POST/v1/tenants/{tenant}/tasks/{id}/progress
处理中上报实时进度。请求体：{ "message": "正在分析代码...", "percent": 20 }（message 必填；percent 可选 0-100；data 可选 JSON）。产生 task.progress 事件，可经事件端点 / SSE 流读取。
POST/v1/tenants/{tenant}/tasks/{id}/ack
确认成功完成。请求体：{ "lease_id": "...", "agent_id": "...", "result_ref": "...", "token_usage": { "prompt_tokens": 0, "completion_tokens": 0, "total_tokens": 0 } }（lease_id 必填；绑定 Key 需 agent_id；建议带 result_ref——下游 Agent 读取它；token_usage 可选）。响应 200：{ "status": "completed" }。重复 ACK 幂等——预算绝不重复结算。对过期租约 ACK 返回 400；该任务已被重投。Token 用量：Janus 按固定单价（$0.00003/token）估算费用、按租户与 Agent 记账，并执行已配置的估算日费用阈值——估算不等同于模型服务商的实际账单。
POST/v1/tenants/{tenant}/tasks/{id}/nack
否定确认——重新入队或进入死信。请求体：{ "lease_id": "...", "agent_id": "...", "retriable": true, "error": { "code": "TRANSIENT", "message": "上游超时" } }。retriable: true 按退避调度重试（retry_scheduled）；false 进入邮箱 DLQ（可经 /replay 重放）。
GET/v1/tenants/{tenant}/tasks/{id}
获取任务详情：{ "id", "status", "result_ref", "error", "attempt_count", "replay_count", "created_at", "completed_at", "envelope", ... }。状态：queued · claimed · running · retry_scheduled · approval_pending · completed · failed · dead_lettered · cancelled · expired。终态除 replay 外不再转移。
GET/v1/tenants/{tenant}/tasks
列出任务，支持可选过滤（状态、邮箱、来源）。
GET/v1/tenants/{tenant}/tasks/{id}/events
任务事件轨迹（生命周期 + 进度）：task.created · task.queued · task.claimed · task.started · task.progress · task.completed · task.failed · task.retry_scheduled · task.dead_lettered · task.cancelled。进度 payload 携带 progress 端点上报的 percent/message——fan-in 消费者由此读取分支结果。
POST/v1/tenants/{tenant}/tasks/{id}/replay
将任务从 DLQ 重放回 pending 状态。

Catalog 与意图

GET/v1/tenants/{tenant}/catalog
列出在线 Agent 及其能力（名称、描述、schema），供客户端侧匹配使用。
POST/v1/tenants/{tenant}/tasks
意图路由 — 以 target_type: "intent" 和自然语言 target_value 发布任务。Janus 在派发前将其解析为最匹配的能力（配置了 JANUS_LLM_ENABLED 时用 LLM，否则降级关键词匹配）。没有单独的 resolve 端点。

Artifacts

Artifact 存储以内置库形态提供（内容寻址、sha256、租户隔离），本版本尚未暴露公开 HTTP API——没有 /artifacts 端点。大载荷请经 ACK 的 result_ref（如 s3://...）引用。公开上传/下载 API 在路线图中。

错误格式

所有错误都返回标准信封：

{
    "error": {
        "code": "TENANT_MISMATCH",
        "message": "Cross-tenant access denied",
        "details": {
            "request_tenant": "acme",
            "resource_tenant": "evil-corp"
        }
    }
}
HTTP 状态错误码描述
400INVALID_REQUEST请求体格式错误
401UNAUTHENTICATED缺少或无效的 API 密钥
403TENANT_MISMATCH跨租户访问被拒绝
403POLICY_DENIED治理策略阻止了该操作
404NOT_FOUND资源不存在
400INVALID_ARGUMENT租约不匹配或已过期（对服务端已不持有的租约 start/ACK/心跳）——重新拉取任务；投递为至少一次，同一工作可能到达两次
429RATE_LIMITED超出预算或并发限制
500INTERNAL服务器错误

认证

Janus 支持两种认证模式：

  • API 密钥（默认，已启用）— 通过 Authorization: Bearer <key> 请求头传递
  • mTLS — 使用客户端证书的双向 TLS

API 密钥按租户作用域划分。通过 CLI 创建与撤销密钥：

janus api-key create --tenant acme
janus api-key revoke --tenant acme --key-id <id>
完整的 protobuf 服务定义与 gRPC reflection 已在服务端开放。proto 文件见 GitHub 仓库。
