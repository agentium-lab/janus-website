前置条件

  • Docker 与 Docker Compose（推荐方式）
  • Python 3.10+（用于 SDK 示例）
  • 或从源码构建：Go 1.25+、PostgreSQL 13+、NATS 2.10+（JetStream，可选——PostgreSQL 默认即队列）、Redis 7+

1. 获取 Janus 源码

Janus 仓库自带生产可用的 Dockerfile 和 docker-compose.yml。克隆即可获得所需的一切：

git clone https://github.com/agentium-lab/Janus.git
cd Janus

克隆后你会得到：

  • Dockerfile — 多阶段构建（Go 编译 → 精简 Alpine 运行时），产出 janus-api 二进制
  • docker-compose.yml — 一条命令启动 Janus + PostgreSQL + NATS + Redis
  • configs/janus.example.yaml — 参考配置文件
  • migrations/ — PostgreSQL 数据库迁移（启动时自动执行）

2. 用 Docker Compose 启动

在仓库根目录下，一条命令即可构建 Janus 镜像并启动全部四个服务（janus-api、postgres:16、nats:2 含 JetStream、redis:7）：

docker compose up -d --build

首次构建需要几分钟（编译 Go 二进制）。后续启动是即时的。验证所有服务健康：

curl -s http://localhost:8080/healthz
# → {"status":"ok"}

curl -s http://localhost:8080/readyz
# → {"status":"ready"}  (检查 PG + NATS + Redis 连通性)

获取 API 密钥。鉴权默认开启，栈会为租户 acme 种入公共开发密钥。现在导出它——后续每一步都会用到：

# 种入的开发密钥（设计上公开——仅限开发）： 
export JANUS_API_KEY=janus_e12ebdab09a71c856666756ab26fd12db630041a96559b74066f66820c1d6d48

Janus 暴露两个端口：

  • 8080 — HTTP REST API 与协议网关
  • 9090 — gRPC API

5. 安装 Python SDK

pip install janus-broker

6. 发布一个任务

创建文件 publish.py：

import os

from janus_broker import (
    CreateMailboxRequest, JanusClient, Payload, PublishTaskRequest,
    RegisterAgentRequest, Target, TaskEnvelope,
)

# API key from step 2 (seeded dev key, or one created via the CLI)
client = JanusClient(
    "http://localhost:8080",
    tenant_id="acme",
    api_key=os.environ["JANUS_API_KEY"],
)

# 1) Register the agent that will consume the task
client.register_agent(RegisterAgentRequest(
    id="reviewer",
    display_name="Code Reviewer",
    capabilities=[{"capability": "code_review", "description": "reviews source code"}],
))

# 2) Create its mailbox
client.create_mailbox(CreateMailboxRequest(id="review-mb", agent_id="reviewer"))

# 3) Publish a task into that mailbox
resp = client.publish_task(PublishTaskRequest(
    id="task-001",
    source_agent="product",
    target_type="mailbox",
    target_value="review-mb",
    envelope=TaskEnvelope(
        task_id="task-001",
        tenant_id="acme",
        source_agent="product",
        target=Target(type="mailbox", value="review-mb"),
        payload=Payload(type="code_review", content='{"pr_url": "https://github.com/org/repo/pull/42"}'),
    ),
))
print("Published:", resp["id"])
$ python publish.py
# → Published: task-001

投递目标类型

Janus 支持五种任务投递方式：

  • mailbox — 投递到指定邮箱（队列）。适合点对点工作流。
  • agent — 投递到特定 Agent。Janus 自动将 agent-2 解析为其活跃邮箱。
  • capability — 描述你的需求,Janus 找到具备该能力的在线 Agent。
  • group — 投递到团队。在 agent 配置中设置 team: "sre",然后以 target_type: "group", target_value: "sre" 发布。
  • intent — 用自然语言描述需求。需要 LLM 配置（JANUS_LLM_ENABLED=true）。Janus 将你的描述映射到最匹配的能力。
# Route to a specific agent
client.publish_task({
    "id": "task-002",
    "source_agent": "product",
    "target_type": "agent",
    "target_value": "reviewer",
    "envelope": {"task_id": "task-002", "tenant_id": "acme",
                 "source_agent": "product",
                 "target": {"type": "agent", "value": "reviewer"},
                 "payload": {"type": "code_review", "content": "{}"}},
})

# 按能力路由（Janus 找到声明该能力的在线 Agent）
client.publish_task({
    "id": "task-003",
    "source_agent": "product",
    "target_type": "capability",
    "target_value": "code_review",
    "envelope": {"task_id": "task-003", "tenant_id": "acme",
                 "source_agent": "product",
                 "target": {"type": "capability", "value": "code_review"},
                 "payload": {"type": "code_review", "content": "{}"}},
})

# 投递给团队（注册时带 team: "sre" 的 Agent）
client.publish_task({
    "id": "task-004",
    "source_agent": "product",
    "target_type": "group",
    "target_value": "sre",
    "envelope": {"task_id": "task-004", "tenant_id": "acme",
                 "source_agent": "product",
                 "target": {"type": "group", "value": "sre"},
                 "payload": {"type": "deploy", "content": "{}"}},
})

7. 拉取并完成任务

创建文件 worker.py：

import os

from janus_broker import AckRequest, JanusClient

client = JanusClient(
    "http://localhost:8080",
    tenant_id="acme",
    api_key=os.environ["JANUS_API_KEY"],
)

result = client.pull_task("review-mb", "reviewer")
if result is None:
    print("No task waiting — mailbox is empty")
else:
    print("Got task:", result.task.id)
    client.start_task(result.task.id, result.lease.lease_id, agent_id="reviewer")

    # ...do the work here...

    client.ack_task(result.task.id, AckRequest(
        lease_id=result.lease.lease_id,
        result_ref="s3://review-result.json",
        agent_id="reviewer",
    ))
    print("Task completed")
$ python worker.py
# → Got task: task-001
# → Task completed

上报进度

Handler 收到 (task, progress)，返回 (result_ref, token_usage) 元组——Worker 自动注入回调：

def process(task, progress):
    progress("Analyzing code...", percent=20)
    progress("Fixing issues...", percent=60)
    return "s3://review-result.json", None  # (result_ref, token_usage)

# Read the event trail from the other side (progress + lifecycle):
for evt in client.get_task_events("task-001"):
    print(evt["event_type"], evt.get("payload"))
# → task.progress {"percent": 20, "message": "Analyzing code..."}
# → task.completed {...}

8. 用 CLI 验证

使用 Janus CLI 查看任务状态：

janus task list --tenant acme
# → task-001  completed  2026-07-31T12:00:00Z

janus mailbox list --tenant acme
# → review-mb  tasks: 1  pending: 0

首次运行常见问题

  • 所有请求 401 / 403——Compose 默认开启鉴权；导入种入的开发密钥（deployments/dev/seed-dev-key.sql）或用 janus api-key create 创建的密钥为 JANUS_API_KEY，并在客户端传 api_key=。
  • 拉取返回 None——邮箱为空或任务尚未入队；再次轮询即可。空拉取是正常结果，不是错误。
  • 能力/团队路由找不到 Agent——路由只考虑已注册且在线的 Agent；先调用 register_agent（带能力声明）并心跳，再发布任务。
