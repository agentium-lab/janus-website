痛点

生产环境中的 Agent 协作痛点

当 Agent 之间直接交接任务，下列每一种故障都会变成线上事故。Janus 居中调度，逐一消除。

📭

任务丢失

Agent 离线时，发过去的任务直接消失

→ Janus 持久化收件箱，离线不丢
🔍

无法追踪

谁调用了谁，传了什么数据，全靠猜

→ 全链审计 + Trace ID
💥

并发失控

下游 Agent 被并发请求直接打爆

→ 预算 + 并发限制
🔐

缺乏管控

谁能调用谁，能传什么上下文，没有规则

→ 策略引擎 + 审批流
💰

成本不可见

哪个团队超了频控、用量是否透明

→ Token / 费用预算控制
🔌

协议碎片化

每个 Agent 框架一套接口，集成成本高

→ A2A / MCP / SDK 统一接入

提交 · 拉取 · 进度 · 确认——中间有租约、预算与身份强制

⇄

接入层

A2A v1 网关 · MCP 网关 · HTTP REST · gRPC——鉴权、scope、智能体身份绑定

核心服务

任务状态机 · 策略与审批 · 预算与账本 · 路由与意图 · 审计

后台 Worker

事务性 Outbox 发布器 · 事件投影 · 租约/重试扫描 · 心跳清扫

⇄

POSTGRESQL

权威状态 + 事务性 Outbox——accepted ≠ queued，审计可重放

NATS · REDIS

JetStream 可选投递面 · Redis 心跳与限流缓存（不存持久事实）

状态先提交 PostgreSQL；Outbox 在提交后才发布到 NATS——PG 状态 永远是恢复源。

核心能力

核心能力

六大支柱，把脆弱的 Agent 直连，变成可控、可观测的生产级网络。

📡 实时流式

  • v1.4 新特性：SSE 实时任务进度
  • Agent 上报就像打日志：progress("分析中...", 60)
  • 任意 SDK / Console / A2A 客户端可订阅
  • 任务完成后流自动关闭

🔄 持久投递

  • 仅靠 PostgreSQL 即可运行——NATS 降级为可选加速层
  • PostgreSQL 事务状态 + 事务性 Outbox；NATS 为可选投递层
  • Agent 崩溃后自动恢复，任务不丢失
  • ACK/NACK 幂等，至少一次投递——Broker 状态不会重复结算，外部副作用需由 worker 幂等
  • 自动重试 + 死信队列 + 手动重放

⚖️ 治理控制

  • 策略引擎：谁能调用谁，能传什么数据
  • 预算控制：按租户/智能体的 RPM / TPM / 并发准入限制（Broker 自计数；Redis 故障默认放行；Token/成本为智能体上报的可见性，TPM 为准入估算）
  • 人工审批：高风险任务需人工确认
  • 全链审计：每一步都有据可查

🧭 能力路由

  • 按能力匹配 Agent，不是写死目标
  • 硬约束：在线 / 权限 / 容量 / 预算
  • 语义排序：候选 Agent 智能打分
  • 能力路由（自然语言意图解析：路线图中）

  • ACP Gateway（Manifest / Runs）— 已弃用 → A2A （Sunset 2026-12-31）
  • MCP Gateway（Tool Call / Resource）

📊 可观测性

  • Prometheus 指标（16+ 核心指标）
  • OpenTelemetry 链路追踪
  • 结构化 JSON 日志
  • Grafana 预置面板

快速开始

5 分钟跑通

一条命令启动代理，几行 SDK 即可发布并完成你的第一个持久化任务。

1. 启动 Janus 
$ docker compose up -d
2. Python SDK 发任务 
from janus_broker import JanusClient

client = JanusClient("http://localhost:8080", tenant_id="acme")
client.publish_task({
    "id": "task-001",
    "source_agent": "product",
    "target_type": "mailbox",
    "target_value": "review-mb",
    "envelope": { ... }
})
3. Agent 拉取并完成 
result = client.pull_task("review-mb", "reviewer")
client.start_task(result.task.id, result.lease.lease_id)

# 处理任务...

client.ack_task(result.task.id, {
    "lease_id": result.lease.lease_id,
    "result_ref": "s3://result.json"
})
